## 最大的三个"名不副实"（宣传 vs 实现）

这是我认为最值得增强的地方——About 页承诺了但代码里没有：

**1. "AI Chat Assistant" 是假的** 🔴
[ChatPanel.tsx:173](apps/web/src/components/ChatPanel.tsx) 的 `getBotResponse` 是一堆 `if (input.includes('schedule'))` 硬编码字符串，不是真 LLM，后端也**没有任何 chat/AI 路由**。
→ 增强：加后端 `/chat` 接口接 **Claude API**，把该用户的车型 + 保养历史作为 context 传入，变成真正能答"我这台 2020 Toyota 该做什么保养"的助手。这是你已经在用 Claude 的天然延伸。

**2. "Smart Reminders / Never miss an oil change" 不存在** 🔴
数据模型存了 `nextDueDate`/`nextDueMileage`，但**没有任何地方计算"快到期/已逾期"或发通知**。
→ 增强：先做"到期提醒"——首页/车详情高亮 due/overdue 的保养项（纯前端聚合即可，零新依赖）；进阶再加定时任务 + 邮件/推送。

**3. "Cost Analysis / 花费趋势" 不存在** 🟡
`cost`/`mileage`/`date` 数据都有，但没有任何聚合或图表。
→ 增强：后端加聚合接口（按月/按车汇总花费），Web 用图表（你项目里正好有 dataviz skill / 可上 Recharts）。这是把已有数据变成价值的低成本高回报点。

## 基础设施短板（不是功能，但影响生产可用性）

| 问题 | 位置 | 风险 |
| --- | --- | --- |
| 登录**无限流** | 无 rate-limit | 撞库/暴力破解 |
| 无 **helmet** 安全头 | server.ts | XSS/点击劫持 |
| `cors()` 全开 | [server.ts:19](apps/backend/src/server.ts) | 任意域可调 API |
| token 存 **localStorage** | AuthProvider | XSS 可窃取；建议 httpOnly cookie |
| 头像 base64 进 DB | userController | 文档膨胀、无 CDN、5mb 请求体；应转对象存储存 URL |
| 无找回密码/登出/刷新 | authController | 7 天内 token 无法吊销 |
| 无分页/搜索 | car/maintenance controller | 数据多了列表全量拉 |

## 我的优先级建议

**如果只做 3 件事**，按 ROI 排：

1. **真 AI 助手**（接 Claude）—— 把最核心的卖点做实，差异化最大
2. **到期提醒**（先纯前端聚合）—— 成本最低、直击"车主"核心痛点、数据现成
3. **登录限流 + helmet**（后端加两个中间件）—— 半小时的活，堵住最明显的安全洞

**中长期**：mobile 从模板变成真 app（可复用 `@car-doctor/shared` 的 schema + 同一套 API），费用趋势看板，头像转对象存储。

要不要我先挑一个动手？我推荐从 **#2 到期提醒**（快、无外部依赖、能立刻看到效果）或 **#3 安全中间件**（改动小、价值明确）起步；#1 AI 助手最有意思但需要 Anthropic API key 和后端新路由，工作量大些。你定。
